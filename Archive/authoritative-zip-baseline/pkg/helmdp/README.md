# helmdp

## General Overview
This component updates references to dependencies which have been downloaded in the chart files and bundles chart and references for transmission over a DTN.

The process of updating the dependency references is as follows:
1. Parse the list of dependencies generated by `helmdd`
2. Prepare the reference update by unpacking all archives containing subcharts
3. Update YAML and template files
   - If template: This is done using `strings.Replace()` as templates cannot be parsed as YAML
   - If YAML: The YAML is parsed and the values for e.g. the `image` keys are updated directly
4. Create a tar.gz archive from the directory containing the charts and dependencies

## Adding a new resource type to update references for
To add a new resource type for `helmdp` to update, the code has to be modified in some places. In the following, it will be explained using the example of Git repositories.

### 1. Updating templates
Git repositories will most likely be referenced in templates (e.g. for deployments). The `updateTemplate` function reads a Helm template (which due to the placeholders cannot be marshalled by yaml.Marshal) and updates references to point to local alternatives. We therefore need to modify this function to update `git clone` commands:
```go
func updateTemplate(path, registry string, dependencies util.Dependencies) error {
	templateBytes, err := os.ReadFile(path)
	if err != nil {
		return fmt.Errorf("failed to read file %v: %w", path, err)
	}

	template := string(templateBytes)

    // Update git links to point to downloaded repos.
	for git := range dependencies.Git {
		template = strings.ReplaceAll(template, git, strings.TrimSuffix(filepath.Base(git), ".git"))
	}

	// Replace "git clone" commands with "cp -r" to copy downloaded repos instead of fetching remote.
	// XXX: This may result in errors if the git clone does not specify a target directory.
	// XXX: E.g. "git clone github.com/somerepo.git" would become "cp -r somerepo" which is not valid.
	template = strings.ReplaceAll(template, "git clone", "cp -r")

	// Overwrite the file with the new changes.
	if err := os.WriteFile(path, []byte(template), 0644); err != nil {
		return err
	}
	return nil
}
```


### 2. Updating YAML files
Git repositories may not be defined directly in the template. It is possible, that they themselves are templated like so:
```yaml
[…]
containers:
- name: git-fetcher
  image: alpine/git:latest
  imagePullPolicy: IfNotPresent
  command: ["/bin/sh", "-c"]
  args:
  - git clone {{ .Values.assetFetch.repositoryUrl }} {{ .Values.assetFetch.targetPath }}
  volumeMounts:
  - name: asset-volume
    mountPath: /mnt/assets
[…]
```
with a corresponding entry in the `values.yaml`:
```yaml
assetFetch:
  repositoryUrl: "https://github.com/somenamespace/somerepo.git"
  targetPath: "/mnt/assets"
```

We therefore also need to update the `values.yaml` file to point to the local repo. This is fortunately rather simple, as we can easily search for key-value pairs in the parsed YAML. In the `` function we therefore add the following:
```go
// Redirect git links by removing everything but the repository names,
// which coincides with the directories created by helmdl.
for git := range deps.Git { //<- deps is an instance of the Dependencies struct containing a full list of the cloned Git repos
	_, gitRef := findValueKey(n, git) //<- we don't know the key, so we search by value
	if gitRef != nil {
		gitRef.Value = strings.TrimSuffix(path.Base(git), ".git") //<- update the URL (https://github.com/somenamespace/somerepo.git) to "somerepo.git" and trim the suffix so we get the clean directory name (somerepo)
	}
}
```
This was the last change we needed to make to the helm-dtn tooling in order to add a new resource type. All that remains is using `helmdtnt` to transmit the archive over a DTN link and deploy it in the remote cluster.
